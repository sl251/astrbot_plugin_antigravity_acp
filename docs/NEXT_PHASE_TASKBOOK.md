# 下一阶段任务书：宿主工具调用、多模态与可维护认证

> 历史设计与验收记录：以下版本、测试数量及待办保留当时状态。当前 0.2.0 的认证桥、代理、自检与兼容范围以 [README](../README.md) 和 [CHANGELOG](../CHANGELOG.md) 为准；历史实例成功不替代本次发布验收。

更新：2026-11-07。性质：**待实施任务书，不是已实现能力声明**。

## 1. 目标与交付边界

将现有仅文本的 `agy_acp` Provider 发展为可以接入 AstrBot 日常对话工作流的适配器，优先实现：

1. 官方登录态在隔离会话下可靠使用、刷新及故障定位。
2. **AstrBot 宿主工具调用闭环**：模型提出调用 → 宿主校验/授权 → 宿主执行 → 正确回填 → 模型继续回答。
3. 图片输入及图文多轮；音频、视频、PDF 等按独立能力探针再决定，不与图片一起宣称支持。
4. 流式、历史、取消、资源回收及配置体验随上述能力一起完善。

默认仍为本机原生部署；容器是可选部署方式。不得为了工具调用移除隔离、开放 AGY 默认 shell/文件工具，或要求用户搭建公网工具服务。

本轮仅编写计划。本文没有授权执行高风险工具、切换生产主模型、复用其他账号凭据或使用未约定的付费模型。

### 2.3 必须先解决的缺口

- 显式隔离目录改变认证搜索路径，普通 `agy models` 成功不等于隔离 ACP 可用。
- `Authentication required` 当前误归为 `UPSTREAM`，需要分类为 `AUTH` 并给出准确检查路径。

- 原文档中的“工具阶段实现 MCP 挂起/回填”只是早期设想，不是已确认的 ACP/AGY 能力；必须先过协议决策门。

## 3. 总体原则与非目标

- **宿主掌握工具权限**：不得把模型同意、ACP permission 请求或模型提示当成用户授权；工具权限、危险操作确认和执行上下文沿用宿主机制。
- **一个工具只有一个执行者**：不得同时由 AGY 内置工具和 AstrBot runner 执行同一调用。
- **协议事实优先**：不把 `tool_call` 通知冒充尚未执行的函数调用，不发明暂停/恢复或结果回填方法。
- **失败关闭**：没有宿主授权上下文、会话关联丢失、能力不支持、桥失联时不得退化为自主执行。
- **历史与工具结果均是不可信数据**：不得提升为系统提示、凭据或本地命令；不拼接 shell。
- **资源与副作用有边界**：有上限、有超时、可取消；有副作用的工具不自动重试。进程内去重不能宣称跨崩溃 exactly-once。
- **能力按实测声明**：宿主模型元数据可能宣称支持工具/图片，不等于本 Provider 已支持；UI 只暴露适配器与当前模型均可实现的能力交集。
- 不做账号池、自动换号、客户端身份伪装、二进制补丁或绕过上游限制。暂不做跨机远程工具代理、任意代码执行与浏览器电脑控制。

## 4. M0：协议与宿主契约决策门（首先完成）

### 4.1 只读核查与最小探针

记录实际版本、能力协商字段及脱敏协议夹具，核对当前 ACP 规范、官方 CLI 文档/实现和 AstrBot v4.29.4 源码：

- `initialize`、`session/new`、模型/思考配置；MCP transport、动态 schema、可用客户端能力及实际支持程度。
- `session/update` 的 `tool_call` / `tool_call_update` 是观察性状态还是可驱动执行的控制面；调用是否已经执行。
- 工具执行前是否有完整且稳定的 name、call ID、arguments；是否存在**官方且实测可用**的结果回填及继续生成机制。
- AstrBot `LLMResponse` 工具字段、`func_tool` / `tool_choice`、assistant 工具记录与 role=tool 历史、流式聚合、runner 的权限/执行/上下文入口。
- 图像 prompt 能力、可接受内容块、大小与 MIME 限制；不把纯文本模型目录当作图片探针。

### 4.2 路线比较与选型产物

提交 `docs/TOOL_BRIDGE_DESIGN.md`，选择且解释一条主路线；不要实现两个重复执行引擎。

**路线 A：Provider 返回原生工具请求，由现有 AstrBot runner 执行。**

优先保持宿主既有语义。但前提是实际协议能在执行前返回完整调用，且后续调用能把宿主结果回到同一模型推理过程；要验证 outstanding prompt、会话锁及流关闭后的续接。单纯解析通知不满足前提。

**路线 B：受限 MCP 桥把执行转交宿主。**

仅在 AGY 确认支持该 transport/配置时采用。优先 stdio 或仅本机受保护传输，不默认新增公网端口。MCP 调用须进入宿主统一的授权/执行上下文，不可直接调用任意 Python 函数绕过 runner。若需 runner/executor 适配，应明确兼容入口、维护成本、调用与结果的持久历史语义。

候选时序为 `AGY MCP call → 会话级桥 → 宿主授权/执行 → MCP result → 原 session/prompt 继续`：这是保持原调用等待，不是协议级暂停/恢复。若需要交回 AstrBot 原生 runner，须设计 pending-call broker 及跨 Provider 请求的关联状态机；若桥接宿主 executor，须逐项列明并补齐 runner 的 hooks、调用预算、直接发消息、历史和中止语义。`func_tool` 可能是 `skills_like` 模式的轻量 schema 集，不能假设其中总有可调用 handler；续轮结果主要来自 contexts，不能只实现 `tool_calls_result` 参数。ACP 展示 ID、MCP 请求 ID、宿主 tool call ID 必须分别建模、显式关联。

两条路线均不通时：交付阻塞证据、可选宿主扩展方案及代价，保留文本模式；不得用字符串伪装工具调用，或让 AGY 默认执行工具以“完成任务”。

**M0 验收**：方案附成功/失败真实探针、数据流和时序图、权限边界、重入/锁分析、所需最小宿主变更；标明支持与不支持的组合。探针使用无副作用 echo 工具，不访问用户文件和账号数据。

## 5. M1：认证与错误处理正式化（P0）

### 工作项

- 将会话配置隔离与认证存储分开；先找官方支持的独立认证位置/后端机制，再考虑明确 opt-in 的文件后端适配。
- 对版本及认证后端做能力检查；Linux 文件方案不能默认套用于 macOS 钥匙串、Windows Credential Manager 或其他 keyring。
- 不读取、打印、上传或自行刷新 OAuth token，不在仓库提交凭据或真实账号标识，不自动复制其他系统用户/机器的登录态。
- 若保留桥接：校验目标归属、路径、父目录权限和符号链接边界；认证状态不放在可清理会话目录；不能简单把整个 HOME/.gemini 暴露给隔离 agent。
- 验证 CLI 的凭据写入/原子替换行为；如果不得不共享认证后端，说明跨 Provider、普通 CLI 与插件进程的刷新协调策略。仅 `max_concurrent=1` 不代表全账号串行化。
- 修正 `Authentication required` 分类；区分 AUTH、网络、限流/额度、权限/账号限制、模型不支持。无上游证据不能把 403 一律写成封号。
- 诊断只输出脱敏类别、操作建议、版本/能力与阶段，不保留原始 stderr 或完整敏感错误。

### 验收

- 同一实例官方登录 → 原生隔离 `session/new` → 真实短回复成功，不依赖未记录的机器私有补丁。
- 未登录、撤销/失效、权限错误、错误路径分别可复现并安全报错；无凭据泄露。
- 用 fake 后端覆盖原子替换、失败刷新、并发刷新和清理；真实刷新必须通过受支持流程观察，不篡改生产 token 到期时间。若未观察自然刷新，明确列为发布限制。
- 取消、重载、超时和清理只删除会话数据，持久认证仍在；退出后没有私有副本或意外 token 文件。

## 6. M2：AstrBot 工具调用 MVP（核心优先）

### 6.1 最小功能

- 根据 M0 选定路线接入当前请求 `func_tool` 的宿主可用工具集合，不曝光被禁用/未授权的工具；工具 schema 改变时刷新或重建，不复用旧许可。
- 名称映射可逆且无碰撞；参数保留 JSON 类型，按宿主可接受 schema 校验。未知工具、参数无效、重复 ID、越权请求均明确失败。
- 稳定关联 provider、会话、轮次、tool call ID、宿主执行上下文与结果，禁止跨群/私聊串线。
- 默认关闭工具能力；显式启用后也只允许宿主现有权限范围。`tool_choice` 的 none/auto/required/指定函数若不可实现就明确拒绝，不假装遵循。
- 首先只做一个只读工具闭环，再覆盖连续多次调用与错误结果；并行调用在关联和取消正确后单独开启。
- 工具返回文本/结构化结果先打通；二进制、图片等工具结果独立协商，不能偷偷转成无意义字符串。
- 宿主已批准的函数与 AGY 内置文件/终端权限分离；保留默认拒绝 AGY 任意 shell、文件和全局 MCP/插件的隔离策略。

### 6.2 状态机、历史与流式

设计明确状态：生成中 → 等待工具/授权 → 执行中 → 等待结果/续接 → 完成/取消/失败；给出路线 A/B 的实际映射。

- 绑定原请求的用户、群、会话、persona 和允许工具集合；没有上下文的摘要/健康检查等匿名调用不得获得聊天权限。
- assistant tool call 与 tool result 按宿主格式保存；支持含历史工具记录的新请求，不再一概拒绝，但拒绝未知或未闭合的关联。
- 重建、压缩、回滚按完整工具交换单元处理，不留下孤立 tool result，不把 tool 内容提升为指令；不能伪称支持完整原生历史而实际只拼文本。
- 流式工具参数按实际协议聚合；完整且验证通过前不执行。重复、乱序、迟到更新不触发二次执行；工具事件不得污染可见正文或 reasoning。
- 停止消费、请求取消、授权超时、宿主停用/重载和进程 EOF，均解除等待并回收；取消后迟到结果不能恢复已结束会话。
- 有副作用调用取消/崩溃后，明确区分“未执行”“已完成”“状态未知”；不自动重放未知调用。
- 设单轮工具次数、执行/审批时限、结果字节预算与最大并发；大结果遵循宿主处理机制或明确报错，不静默截断结构化值。

### 6.3 工具验收集

1. 确定性 echo 工具：参数由模型发起，宿主执行一次，结果返回模型，最终答案引用真实结果；三段证据齐全，不能只看回答像成功。
2. 只读检索工具：多步骤调用后总结；先用本地固定数据夹具保证可复现，再做获准的真实联网测试。
3. 参数类型错误、未知工具、无权限、缺失上下文：工具执行次数为零。
4. 需要审批的无害模拟操作：拒绝/超时执行次数为零，批准只执行一次；生产高风险操作不作为默认测试。
5. 连续调用、同轮多调用、重复 ID、乱序更新、部分参数、工具自身异常与超大结果。
6. 工具等待/执行各阶段取消，两个群及两个 Provider 并发；无串结果、死锁、孤儿进程或重复副作用。
7. 20 轮含工具历史、历史编辑/压缩/回滚、插件重载后按设计重建；记录支持边界。
8. 直接 Provider 调用和真实 AstrBot runner 均测试；原文本/流式/权限拒绝回归仍通过。

**M2 通过条件**：运行中 AstrBot 原有聊天 runner 完成至少一次真实只读工具闭环，并有宿主执行计数/关联证据。Provider 假数据、仅 ACP 工具通知或模型自称执行过，不算通过。

## 7. M3：图片与图文多轮（工具 MVP 后）

- 核对 AstrBot 消息对象、`image_urls`、`extra_user_content_parts` 和 contexts-only 路径，确保相同附件只送一次；宿主若预先删除附件须说明配置限制。
- 使用实际 ACP 支持的 image content block，不把 base64、文件路径或 URL 当作普通文本冒充视觉输入。
- 本地文件仅允许已授权媒体位置，处理符号链接/路径穿越；远程 URL 如需下载，校验跳转后目标，阻断回环、私网、链路本地与元数据端点，限制超时、数量、字节和解码像素。
- 校验实际 MIME、文件签名和格式支持；无文本但有图片不能仍被“用户文本为空”拒绝。处理图片失效、非图片响应、尺寸超限、格式不支持等错误。
- 历史指纹包含媒体内容身份；考虑临时文件生命周期、会话复用、历史重建和总预算，禁止清理其他会话或用户原件。
- 模型/CLI/Provider 任一不支持则明确拒绝或由用户选择宿主图片描述降级，不静默忽略图片。
- 更新 UI 能力为真实支持的交集；继续默认关闭音频、视频、PDF、图片生成等未验证项。

**验收**：自制不含隐私的单图、双图对比、纯图输入、图文两轮、编辑附件后重建、图片与工具混合轮次；模型能回答必须读图才知道的可核查细节。下载失败/恶意 URL/路径/超大图片不越权、不泄漏、不留临时媒体。fake 测试覆盖边界，真实模型测试独立记录。

## 8. M4：可用性与后续扩展（按需求选做）

- 诊断与配置：显示 CLI/协议能力、认证检查阶段、工具/图片实际支持状态；解释插件全局配置与 Provider 模型配置的区别。
- 安全用量展示：只用官方可用接口和真实返回计数；区分模型余额、窗口与未知状态，不猜额度、不自动换号。
- 音频/视频/PDF：每项各自验证入口、格式、大小、历史和能力声明，通过一项只开启一项。
- Windows/macOS 原生与 Linux 容器分别验证认证后端、启动与进程树清理；未测平台保持未验证标记。
- 持久恢复、跨机 IPC、更多模型家族另立范围；不因工具桥实施顺带开放所有 CLI 模型。

## 9. 建议代码划分与配置契约

以下是职责建议，不是必须照搬的文件名：

| 位置 | 主要责任 |
|---|---|
| `auth.py` / `process.py` | 官方认证后端适配、隔离和启动能力探测 |
| `tools.py` / 可选 `mcp_bridge.py` | schema、会话关联、宿主工具桥与权限入口 |
| `messages.py` / `media.py` | 文本/工具/图片归一化、历史和媒体安全 |
| `transport.py` | ACP 解析与控制面，不在 stdout reader 阻塞等待工具/授权 |
| `sessions.py` | 状态机、复用键、schema/媒体变动、取消和资源池 |
| `provider.py` / `main.py` | 宿主合约、能力注册、生命周期和流式转换 |
| `errors.py` / `tests/` | 分类脱敏与红绿回归 |

- 新增开关须默认保守，文档/JSON schema/类型校验/测试同步更新；配置升级不能默认打开工具或媒体。
- 能力与工具 schema 进入会话复用判定；人格、模型、思考档位、账号认证后端或权限集合变动时不能错误沿用旧状态。
- 新增依赖前说明必要性、版本、许可证和跨平台成本；不引入仅为方便而需要的常驻公网服务。

## 10. 分阶段提交与完成定义

建议拆成可独立审查的 PR；先满足依赖，再推进下一阶段：

1. **协议探针与架构文档**：M0，明确路线和阻塞项。
2. **认证可靠性与错误分类**：M1，含迁移说明及刷新限制。
3. **工具闭环 MVP**：M2，先只读串行，再异常/流式/历史及有界并发。
